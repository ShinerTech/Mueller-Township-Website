# AI Agent Protocol: Blog Maintenance

This repository uses a custom, Python-based static site generator for the blog, which operates entirely independent of Jekyll. Future AI agents must strictly adhere to this protocol when modifying or adding blog posts to ensure the site remains perfectly functional and testable locally.

## 1. Architecture Overview
- **No Jekyll**: The repository contains a `.nojekyll` file. GitHub Pages will serve the HTML files exactly as they are committed. Do NOT attempt to use `jekyll serve`, use Liquid syntax, or configure Jekyll plugins.
- **Build Script**: The entire blog is generated by a single Python script: `build_blog.py`. 
- **Templating Engine**: The layouts (`_layouts/default.html`, `_layouts/post.html`, and `blog/index_template.html`) use standard **Jinja2** templating syntax.

## 2. Protocol for Adding a New Blog Post
When requested by the user to create or process a blog post, an AI agent MUST execute the following steps:

1. **Create the Markdown File**: 
   - Create a new `.md` file in the `_posts/` directory.
   - The filename MUST follow the format: `YYYY-MM-DD-title-of-post.md`
   - Include the following YAML front matter at the top of the file:
     ```yaml
     ---
     layout: post
     title: "Your Post Title"
     date: YYYY-MM-DD
     author: "muellertownship"
     ---
     ```
   - Add the Markdown content below the front matter.

2. **Compile the Blog**:
   - Run the build script from the root workspace directory using terminal command: `python build_blog.py`
   - This script will parse the Markdown, apply the Jinja2 templates, and generate the physical static `.htm` files (e.g., `blog/title-of-post.htm`).
   - The script automatically rebuilds the `blog/index.htm` file to include the new post on the main blog page.

3. **Commit the Changes**:
   - Both the source `.md` file AND the generated `.htm` files must be committed and pushed for the live site to update.

## 3. Modifying Layouts or Templates
- If you need to modify the structure of a blog post, edit `_layouts/post.html`.
- If you need to modify the blog listing page, edit `blog/index_template.html`. **DO NOT edit `blog/index.htm` directly**, as your changes will be permanently overwritten the next time the build script runs.
- Always run `python build_blog.py` after making any changes to the layout templates to regenerate the static files.

## 4. Comments System (Utterances)
- The blog utilizes **Utterances** for comments, which relies on GitHub Issues in the `ShinerTech/Mueller-Township-Website` repository.
- The Utterances client script is hardcoded inside `_layouts/post.html`. Do not alter or remove it unless specifically requested by the user.
